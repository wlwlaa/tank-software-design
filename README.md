# tank-software-design

Учебная игра на Java и LibGDX. Управление танком: стрелки или WASD.

## Домашнее задание 3: OCP и DIP

Ветка `hometask-3` основана на последнем коммите `hometask-2` (`e30d280`).
По заданию Pull Request направляется из `hometask-3` в `hometask-2`.

| Было | Стало | Принцип |
| --- | --- | --- |
| `Field` хранил только `Tree` | `Field` принимает любые реализации `Obstacle` | OCP, DIP |
| `Tank` зависел от `Field`, время движения было константой | Проверка движения задаётся через `MovementPolicy`, время шага передаётся в конструктор | OCP, DIP |
| `MovementInputAction` обращался к `Gdx.input`, знал `Tank` и фиксированные клавиши | Зависит от `KeyState` и `MovementTarget`, получает список `DirectionKeyBinding` | OCP, DIP |
| `TankGame` создавал модели, обработчики и графику | `GameSession` работает с `InputAction`, `Updatable` и `GameView`; зависимости собирает `DesktopGameFactory` | DIP |
| `FieldRenderer` создавал и рисовал деревья, `TankRenderer` зависел от `FieldRenderer` | Список `SceneRenderer` расширяется новыми реализациями; позиционирование задаётся через `TilePositioner` | OCP, DIP |

`DesktopGameFactory` — точка сборки приложения. Здесь выбираются карта,
текстуры, начальные координаты, время шага (0,4 секунды), клавиши и
интерполяция. Изменение этих настроек не требует изменения игровой логики.
Фабрика вызывается в `TankGame.create()`, когда графический контекст уже готов.

Для нового препятствия реализуйте `Obstacle` и передайте его в `Field`.
Для другого управляемого объекта реализуйте `MovementTarget`; для другого
источника ввода реализуйте `KeyState`. Для нового объекта сцены реализуйте
`SceneRenderer` и включите его в список представления. Конкретные реализации
подключаются в точке сборки; ядро при этом не меняется.

Модель использует `GridPoint2` и числовые функции LibGDX, но не зависит от
глобального ввода, рендереров или графического контекста. Запрет нового шага
во время движения обеспечивается самим `Tank`, а не только клавиатурой.
Представление освобождает текстуры, рендерер карты, карту и `Batch`.

## Запуск и проверка

Проект использует Gradle 6.1.1. Для этого wrapper используйте JDK 13
(системный JDK 21 с этой версией Gradle несовместим).

```sh
./gradlew test
./gradlew run
```

При нескольких установленных JDK на macOS:

```sh
JAVA_HOME=$(/usr/libexec/java_home -v 13) ./gradlew test
JAVA_HOME=$(/usr/libexec/java_home -v 13) ./gradlew run
```

Тесты проверяют границы и препятствия, движение и длительность шага,
настраиваемые клавиши и их приоритет, защиту от повторного шага,
последовательность ввода/обновления/отрисовки и позиционирование спрайтов.
Интеграционная проверка `GameSession` запускает ввод и модель с заменой
представления без окна и OpenGL.

Проверка рефакторинга: 28 тестов прошли, ошибок и падений нет.
Запуск окна на текущем Mac с ARM JDK 13 останавливается при загрузке
`libgdx.dylib` из существующих зависимостей. Та же ошибка воспроизводится
на исходном `hometask-2` до создания сцены; визуальная проверка не выполнена.
